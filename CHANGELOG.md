# Changelog

## Unreleased

- `demo.sh --check` requires the eight tools of akko-mcp-trino 0.7 and accepts only the tools a later version is known to add (`KNOWN_EXTRA_TOOLS` in `demo/demo.py`, today `profile_table`, from 0.8); any other tool fails the check. Before, it required exactly the eight, and failed on 0.8.
- `tests/smoke.sh` proves the token exchange from Keycloak's own events (`TOKEN_EXCHANGE`, turned on for the run through Keycloak's admin CLI): one exchange for carol, by the client `akko-mcp`, for the audience `trino`, from a token of `sandbox-mcp`, and none before the demo. Before, it read an HTTP log line of the server, which akko-mcp-trino 0.8 no longer writes (it sets the `httpx` log to `WARNING`). New bench ids `SEC-SMK-027` and `SEC-SMK-028`.
- `catalogs/compose.atlas.yaml`, profile `catalogs`: Apache Atlas 2.4.0 as a data catalog, for the context of akko-mcp-trino 0.8 in `describe_table` and `describe_schema`. `catalogs/atlas/Dockerfile` builds Atlas from the official source release, checked against its published SHA-512, with HBase 2.5.0 and Solr 8.11.3 from the ASF archive, each checked against its SHA-512. `catalogs/seed.py` writes the demo catalog through Atlas's REST API v2: descriptions, the glossary `Sales` (served) and `Compliance` (not served), a synonym, a term attached to `crm.customers` only, a renamed table, a deleted table and column, and a cluster no catalog maps. The server reads Atlas with `mcp_reader`, of Atlas's role `DATA_SCIENTIST`, whose password is drawn at random. The canary `demo.mcp.canary` (`catalogs/canary.sql`) is hidden from everyone.
- `tests/context.sh`, `tests/compose.v08.yaml` and `tests/compose.v08.gateway.yaml`: the checks of that context, directly and, with `GATEWAY=1`, behind Trino Gateway. With akko-mcp-trino built from commit `588e91a`, every check passes, alone and behind the gateway. Built from `0e0159c`, one failed: when Atlas is frozen past the deadline, the server left the request's connection open.
- The policy hides `accounts.opened_on` from analysts (`FilterColumns` and `SelectFromColumns`), filters salary payments out of their transactions (`category <> 'salary'`), and hides the table `demo.mcp.canary` from everyone.

- `bench/`, step B0: one entry point (`bench/run.sh security|perf|correctness`), a preflight that refuses a host short of memory, disk or processors, a dated result per run (`bench/results/`, checked against `bench/schema/result.schema.json`), stable ids for every check of `tests/smoke.sh`, `tests/gateway.sh`, `tests/v07.sh` and `tests/v071.sh` (`bench/security/cases.yaml`), a gate against a baseline per pair (`bench/compare.py`, `bench/baselines/`), the marker scanner (`bench/lib/leaks.py`, played by `bench/security/leaks.sh`), the k6 script checked against the MCP Inspector (`bench/perf/`), and the memory sampler (`bench/lib/memsample.sh`). CI plays the bench's tests and checks every committed result.
- `agent/run.py`: the 95% Wilson interval of the right answers, the right answers per question by a stable id (`questions.json` gives each an `id`), the unstable questions, the (server, model) pair a baseline holds for, and `--baseline`, which applies the correctness gate.
- akko-mcp-trino 0.7.2 by default (`compose.yaml`, and the image name the agent harness reports). The server reads the user from `preferred_username` (`MCP_JWT_USER_CLAIM`): from 0.7.1 it reads `sub` by default, and Keycloak's `sub` is a UUID the policy does not know.
- `tests/v071.sh` and `tests/compose.v071.yaml`: the read allow-list of 0.7.1 and later, directly and, with `GATEWAY=1`, behind Trino Gateway. `SHOW STATS`, `EXPLAIN`, `SHOW CREATE`, `SHOW GRANTS` and `SHOW SESSION` are refused, `explain_query` answers without a plan, what an agent needs still works under the same rules, and `MCP_EXTRA_READ_COMMANDS` opens a command by name.
- `docs/connect-a-host.md` and its French twin: Claude Desktop's bridge is `mcp-remote@0.15.2`, which needs Node.js 20.18.1 or later (its `undici` 7 crashes on Node.js 18 with `ReferenceError: File is not defined`). Both pages point to the full guide of akko-mcp-trino (your own Trino over stdio, a team server, the common errors).
- akko-mcp-trino 0.7.0 by default (`compose.yaml`, and the image name the agent harness reports). `demo.sh` step 5: the same `search_columns` for carol and dave; the word `email` finds `demo.crm.customers.email` for carol and nothing for dave, in a complete search; `--check` asserts both.
- Trino runs with 2048 MB and `MALLOC_ARENA_MAX=2`, on both clusters behind the gateway too: the word searches of `search_columns` and `describe_schema` ask it many metadata queries, its off-heap memory outgrew 1280 MB and the kernel killed it; glibc's per-thread malloc arenas added about 0.5 GB. `tests/compose.v07*.yaml` no longer carry these settings. Measured with `docker stats`: 1460 MiB at rest, 1740 MiB at the peak of the demo; behind the gateway, 3058 MiB at the peak of `tests/gateway.sh`, 3220 MiB during `tests/v07.sh`.
- CI runs `tests/v07.sh` after `tests/gateway.sh`. Until 0.7.0 is on Docker Hub, it builds the server from the core's commit 4105967. A job fails on a placeholder of the typography substitution left in a Markdown file, as `README.fr.md` once held.
- `tests/v07.sh`: the checks of the per-word pass of `search_columns` (akko-mcp-trino PR #31): a complete multi-word search that found nothing returns each word's tables and columns with `words` and `partial`; the question as an agent puts it ("spending category March 2026") finds the category column by its words and nothing for the values; a search whose words match nothing keeps the plain hint; for a viewer, the pass never shows a column the policy hides (the answers go through the leak scan); the advice after a wrong column in `execute_query` names the tables of the caller's own SQL, never one hidden to them. The Trino of the checks gets 2048 MB (`tests/compose.v07*.yaml`): the hundreds of metadata queries outgrew the 1280 MB of the sandbox.
- `tests/v07.sh`: the checks of `search_columns` by words (akko-mcp-trino PR #30): a table found by its name or comment comes in `tables`, without its columns; a column comes in `matches` for a word of its own name or comment; a word found only in a table's comment returns the table alone; a two-word search mixing a table word and a column word returns that column; an empty complete search carries `hint`; more words than the server's limit (read from `--check`) is refused before any query reaches the engine. The checks that read `matches` of the first page follow the cursor and read `tables`.
- OPA batch mode: Trino sets `opa.policy.batched-uri`, and the policy has a `batch` rule that keeps the indexes `allow` accepts, so Trino asks OPA once per listing, not once per column (it saturated OPA's queue on tables of 200 columns). Both paths share the same rules.
- The batch rule answers only the filter operations Trino 482 sends (`FilterCatalogs`, `FilterSchemas`, `FilterTables`, `FilterViewQueryOwnedBy`, and `FilterColumns` by column) and grants nothing to any other. Column masks are batched too (`batchColumnMasks`). `tests/v07.sh` proves from OPA's decision log that Trino asks `trino/batch`.
- `tests/v07.sh`: `search_columns` with a named schema answers kind `schema` when it is missing or hidden (a hidden one looks like a missing one), and finds it for a user who sees it.
- `agent/`: a real-agent harness (`run.py`, `questions.json`, `compose.agent.yaml`). A Mistral or Anthropic model answers five questions about the sample data through MCP as `carol_analyst`; `--repeat N` runs each question N times; the report records, per question, the median and range of the tool calls, of the call at which an expected column first shows and of the tokens, and the right answers out of N. An answer is right only when it is final, names every expected column and none of the question's forbidden ones (fixed in `questions.json` before any run). Keys come from the environment only. `--dry-run` lists the server's tools in the provider's format with no model and no key. Unit tests in `agent/tests`, run by CI.
- `tests/v07.sh`, `tests/compose.v07.yaml` and `tests/compose.v07.gateway.yaml`: the checks of the tools akko-mcp-trino 0.7 adds or changes (`search_columns`, `describe_schema`, paged listings, errors with a `kind`), directly and, with `GATEWAY=1`, behind Trino Gateway. They need 0.7, the default image since 0.7.0, and fail on 0.6.
- Sample data: comments on the crm tables and on some of their columns, and a schema `crm_archive` of twelve empty tables, for listings in several pages.
- For `tests/v07.sh` only, two more catalogs, `tpch` and `tpcds`, generated by Trino itself, for searches that span catalogs (`tests/v07/catalog`, given to the second cluster too behind the gateway by `tests/compose.v07.gateway.yaml`). The sandbox itself keeps its one catalog.
- The policy hides the accounts' `balance` column from viewers (`FilterColumns` and `SelectFromColumns`), and the `tpcds` catalog.
- Trino runs with `hide-inaccessible-columns=true`, on both clusters behind the gateway too: `SELECT *` answers without a column the policy hides, instead of a refusal that names it.
- `demo.sh --check` requires the eight tools of akko-mcp-trino 0.7 (it accepted the six of 0.6 too before 0.7.0 became the default).
- akko-mcp-trino 0.6.0, with its safe defaults: the server accepts only tokens issued for it (audience `akko-mcp`) and exchanges each at Keycloak for a token issued for Trino (OAuth 2.0 Token Exchange, RFC 8693); the user's token is never passed on.
- Keycloak: a confidential client `akko-mcp` with standard token exchange, a target client `trino`, and a public client `trino-cli` whose tokens are issued for Trino. Keycloak serves https too, with its own certificate from the sandbox CA, for the token endpoint. Keycloak is healthy once the realm serves its keys.
- The MCP server's client secret is drawn at random on the first start (`certs`), never written in the repository.
- `demo.sh` shows and checks a write refused before Trino, the message of the `401`, and a valid token issued for Trino refused by the server.
- `tests/smoke.sh` checks that Trino refuses a token issued for the MCP server, that the server exchanged tokens at Keycloak, and that its log holds no client secret.
- The policy refuses `ImpersonateUser` towards any name but the one the token proves, except for the accounts listed in `impersonators` (empty here; akko-mcp-trino's own account in its `impersonation` mode). Before, a user calling Trino directly with their own token could act as another user (found on 2026-10-17). `tests/smoke.sh` proves carol cannot act as alice_admin.
- `./token.sh <user> trino-cli` prints a token for Trino itself.
- `MCP_IMAGE` runs another build of the server.

## 0.1.0 (unreleased)

First version: the open source core of akko-mcp-trino in five minutes.

- `docker compose up -d --wait` starts Keycloak, PostgreSQL with fictional data, OPA, Trino over https with JWT authentication and OPA access control, akko-mcp-trino in `jwt` mode, and the MCP Inspector.
- `./demo.sh`: two users, the same question, two answers; a third user refused; `401` without a token and with a forged one.
- `./token.sh`: a user's access token, to connect an MCP host.
- `tests/smoke.sh`: the end-to-end test, with start time and memory.
- CI: `tests/smoke.sh` on every push and pull request to `main`, on `ubuntu-latest`. The arm64 line (`ubuntu-24.04-arm`) is ready, commented out: GitHub's arm runners are free for public repositories only, so it is enabled when the repository goes public.
- `docs/demo.tape` and a workflow started by hand that records the README animation with VHS. `DEMO_PACE` paces the demo's steps for a recording.
- `docs/demo.gif`, the animation at the top of both READMEs.
- Guide to connect Claude Code, Cursor, VS Code and Claude Desktop.
